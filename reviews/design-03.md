## Round 2 findings

- **Governing/subject copy boundary — partly resolved.** E011 now keeps `orch` protected, makes it locate main's `orchestrator.py`, and copies back only attempt records. These are concrete proposed controls. Present `orch` still executes `SCRIPT_DIR/orchestrator.py`; `REPO_ROOT` follows the executing file (`orchestrator.py:35`); dispatch still copies every changed file (`1078-1085`). The proposed regression is therefore essential before the boundary can be claimed.
- **Protected paths — resolved in the proposal.** E011 retains `.worktrees/**`, `pytest.ini`, `conftest.py`, and `pyproject.toml`, and protects `orch`. Present `PROTECTED_PATTERNS` still additionally protects `orchestrator.py` (`orchestrator.py:114-128`), as expected until the bootstrap change.
- **M01 change control — resolved in the proposal.** E011 now gives the 24.13 affected-milestone list and requests G3 approval. Keeping `./orch` callable from attempt worktrees matches M01's approved interface. M02 remains DRAFT and is marked for revision.
- **Wire observation / false PASS — partly resolved.** A selected cell now has its own capture checker, and every `wire run` must execute every selected checker's negative controls before PASS. This closes the previously identified way to skip `validate-checkers`. The spec still needs a falsification case for a *non-capture* selected checker that accepts its negative; see milestone review.
- **Checker provenance — partly resolved.** `env.json` now records the experiment directory's commit and dirty flag, plus hashes of checker inputs and negatives. A dirty directory is not pinned by its commit, and a checker command's script or executable need not be an `input`. Thus those fields do not necessarily identify the code that produced the verdict. Require a clean checker-source tree or record hashes of the executed checker code and its relevant local dependencies; test a changed checker script with unchanged declared inputs.
- **Capture topology — partly resolved.** Capture privilege failure remains BLOCKED, and 24.20 requires an early OSCORE trial on the intended Hackathon interface. No trial log is present in the reviewed artifacts; the loopback example alone cannot settle L5.
- **E012 build record — resolved in the proposal.** It requires a real corrective builder run and independent verifier with orchestrator-run acceptance and validity logs, without manufacturing an earlier `build.md`. Present M01 implementation gaps remain: `compute_criteria_version` omits `interface` and `size_hint` (`orchestrator.py:1221-1235`), REVIEWED to APPROVED checks only acceptance presence (`2210-2217`), `save_state` does not commit (`1189-1219`), and the CLI has no `integrate` handler (`3786-3810`). These are work for the corrective run, not evidence of success.
- **Illegal BUILDING to ESCALATED edge — resolved.** E012 now keeps M01 in BUILDING and records a corrective run in attempt 01. `TRANSITIONS` (`orchestrator.py:71-112`) confirms that BUILDING to ESCALATED is not an allowed edge. The new run must update the recorded attempt base and builder provenance consistently; current `state.yaml` still names base `f8fdbbca...` and the earlier builder.

## New problem and design challenge

The revised boundary relies on `orch`, but the current prompt renderer substitutes `{orch}` with `./orchestrator.py` and rewrites verifier examples to invoke that file directly (`orchestrator.py:655-675`). The attempt copy can therefore run controller commands despite 24.3's claim that it is executed only by tests. E011 must include a regression in which a verifier follows its rendered prompt from a changed attempt worktree: all `run-tests` and state operations must use main's controller, or direct subject-controller invocation must refuse them. Merely changing the wrapper does not establish this property.

The separate `wire/` package, cells, checkers and bundle serve the stated evidence goal. I find no component without a goal and no stated goal without a proposed component. There is no protocol-specific decoder in the generic runner. The riskiest assumption is that selected checker negatives and recorded provenance make PASS auditable; falsify it early by changing an unlisted checker script in a dirty experiment tree and by running a cell whose vector checker accepts its declared negative.
