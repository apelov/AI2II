# Design review 02

Scope: DESIGN.md 24.3 and 24.20, E011 and E012 at c775404, and the round 1 design findings. I did not write the artifacts. Claims about the present CLI below were checked against `orchestrator.py` and `orch`; the E011 changes are proposals, not implemented behavior.

## Round 1 findings

- **Governing/subject copy boundary — partly resolved.** E011 now requires dispatch to copy only attempt records, requires governing commands to run from main, and names a regression where a builder edit leaves main's `orchestrator.py` unchanged. This addresses the mechanism identified in round 1. The current dispatcher still copies every changed file (`orchestrator.py:1078-1085`), `REPO_ROOT` still follows the executing file (`orchestrator.py:35`), and `_repo_root()` follows it through `MILESTONES_DIR` (`orchestrator.py:134-136`). No claim of enforcement is warranted until the bootstrap commit and tests exist.
- **Protected-path list — resolved in the proposal.** E011 and 24.3 now retain `.worktrees/**`, `pytest.ini`, `conftest.py`, and `pyproject.toml` in addition to the original protected rules. The current `PROTECTED_PATTERNS` still protects `orchestrator.py` and `orch` (`orchestrator.py:114-128`), and `_matches_ownership_rules` checks that list before workflow ownership (`orchestrator.py:1298-1317`), as expected before E011 implementation.
- **24.13 M01 impact — not resolved.** E011 lists M01 as unaffected, but the approved M01 spec explicitly says `./orch` works from the main **or any attempt worktree**, locating main via git. The new 24.3 rule says state, gate, test, and dispatch commands from an attempt copy must refuse. M01's AC3 requires every orchestrator test execution to log, and its interface includes `run-tests` without this new restriction. This changes the approved contract, not merely AC1's implementation. Apply 24.13 change control to M01 and reconcile its interface and criteria before using the new rule.
- **Wire observation and false PASS — partly resolved.** 24.20 now requires an `observes_capture` checker and two capture negatives, and says the checker must assert the exchange. This improves the example. But `wire run`'s PASS rule only requires checker exit 0; it never requires `validate-checkers` to succeed. A checker that accepts any nonempty capture can therefore give a green run even though the separate validity command would reject it. Make checker validation a prerequisite for PASS or explicitly bind the two operations in the evidence workflow.
- **Checker provenance — partly resolved.** The text now honestly calls `family` a declared-policy check rather than proof of independence. The statement that `env.json` pins the experiment's git history is stronger than its defined contents: `env.json` records peer commits/dirty flags, not a checker source revision or author. Record checker provenance if the history is intended to be auditable, or remove that claim.
- **Capture dependency/topology — partly resolved.** The design now treats capture privilege failure as BLOCKED and requires the first OSCORE trial on the intended interface before the runbook. That is a concrete early experiment, but no result is supplied yet; loopback cannot establish Hackathon topology suitability.
- **E012 retroactive build record — resolved in the proposal.** Attempt 02 now starts from the hand-built code and requires a real builder dispatch and a fresh verifier with orchestrator-run acceptance and validity logs. It does not fabricate an attempt-01 `build.md`. Current code still has the inspection-only gaps: `compute_criteria_version` omits `interface` and `size_hint` (`orchestrator.py:1221-1235`), REVIEWED→APPROVED checks only for acceptance (`orchestrator.py:2210-2217`), `save_state` does not commit (`orchestrator.py:1189-1219`), and the CLI handlers have no `integrate` (`orchestrator.py:3786-3810`).

## New problems and design challenge

E012 directs a human to record `BUILDING → ESCALATED → REWORK` for M01 attempt 01. DESIGN.md 24.7 permits `ESCALATED` from `VERIFYING` on INVALID or an attempt limit, not from `BUILDING`. The current `TRANSITIONS` table in `orchestrator.py:71-112` likewise has no `BUILDING → ESCALATED` edge. State a lawful closure for the failed build, or explicitly change the state machine through G3; a manual write that bypasses it would violate the rule the bootstrap is meant to establish.

The extra `observes_capture` field serves the wire-evidence goal, and the generic runner still has no protocol-specific decoder. The separate `wire/` package, cells, checkers, and bundle each serve a stated goal; I find no component with no goal and no goal wholly without a component. The riskiest remaining assumption is that a declared capture checker plus separately runnable negative controls makes a PASS trustworthy. An early falsification is to run a cell with unrelated nonempty traffic and an always-pass checker, without invoking `validate-checkers`; PASS must be impossible. The main-only controller assumption should be tested with a changed attempt copy and a governing invocation from the main worktree.

Outcome: CHANGES_REQUESTED
