## Changes requested

1. **AC4 can pass without the claimed capability.** It rejects an existence-only decrypted checker, but a checker that verifies the expected contents of `{secrets}/client.keys` and never reads `{decrypted}` passes the real run and rejects altered client keys. Add a negative that replaces the decrypted view with malformed or wrong-exchange output while keeping valid secrets, and require rejection. Test this key-file-only mutant. The acceptance criterion must establish that decrypted checker success depends on the decrypted view, not just on key material.
2. **AC6 omits malformed declarations that affect file boundaries and verdicts.** It should reject a non-boolean `observes_decrypted`, a malformed or empty `decrypt` command, and secret names that are absolute, traverse out of `secrets/`, or collide with bundle artifacts. In particular, a peer `secrets: [../capture.pcap]` must fail before any build or process starts. The design must first define this path boundary. Existing M08 validation (`wire/manifest.py`) covers checker input paths and command strings, but has no peer-secret path model to inherit.
3. **The design's decrypt provenance claim has no acceptance case.** AC8 tests bundle integrity after creation; AC1 checks that key logs and output are included. Neither identifies the actual decrypt executable or script when it can change independently of the manifest. Add a falsification case for a changed decrypt tool at the same path, or narrow the design claim. M08 `env.json` currently records git, Python and tcpdump versions, not the decrypt tool.

AC1, AC2, AC3, AC5, AC7–AC10 otherwise state observable outcomes, with wrong keys, cleartext capture, missing secrets, decrypt failures, peer environment isolation, tampering and M08 compatibility as negative cases. AC1 can be tested with a real TLS echo and `tshark` reading the produced pcapng without extra options; `editcap` injection alone does not establish that result. AC3 should also cover a zero-byte or invalid `{decrypted}` file if the artifact is meant to be openable. The existing `wire/checkers.py` substitutes checker inputs or `{capture}`; the secret substitution and decrypt rerun in AC4 are new behavior, so acceptance must verify that the scratch output is used and the canonical bundle output stays unchanged.
