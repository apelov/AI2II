# Milestone review 11

Reviewed `milestones/M10/spec.yaml`, hash **bf9f930174ae** from `./orch show M10`, against DESIGN.md 24.20 and 24.21, the current `wire/` implementation, and both shipped examples. I did not write the spec. This review is not run evidence; I produced no orchestrator run log.

M10 depends on COMPLETE M09, whose chain is M09 → M08 → M01; the DAG is acyclic. M10 is independently implementable after those dependencies, and its S size needs no L justification. The loopback alias, summary and clean-build guidance trace to DESIGN.md 24.20. The deliberately broken example and test-copy repair support the stated first-run and demonstrable-FAIL goal, though the design paragraph does not specify them. AC1–AC3 and most of AC5–AC6 describe observable results, including unsupported OS, tampering and empty input. The following conflicts mean the spec could appear successful without delivering its claimed capability, or cannot pass as written.

1. **AC4 conflicts with the runner's failure path.** `wire/example/udp_echo/src/udp_echo_client.py` exits 1 for a changed echo. `wire/run.py` returns `FAIL` from `run_peers()` immediately when that happens, before `run_checkers()`; it therefore cannot create the required `observes_capture` checker log showing rejection. Specify a runner change that executes the checker on captured packets after a peer failure, or split the criterion into a failing-peer case and a separate capture-checker case. Ensure the corrupted response is actually captured and that the FAIL cannot be satisfied merely by a client exit unrelated to corruption.
2. **AC7 conflicts with changing the example to `loopback`.** `acceptance/M08/test_m08.py::test_ac6_build_failure_missing_binary_capture_failure_blocked` constructs an edit targeting `interface: {IFACE}` and `make_exp()` asserts that target occurs in the example manifest. Once the example contains `interface: loopback`, that unchanged test fails before exercising the runner. AC7's “unchanged” requirement must be reconciled with the changed fixture, for example by an approved compatibility update to the acceptance suite; this cannot be assigned to a builder who does not own `acceptance/**`.
3. **AC2's hardcoded-`lo0` negative does not isolate interface resolution.** `wire/run.py` blocks a dirty experiment directory before starting capture. Editing the shipped manifest in place yields BLOCKED for dirtiness regardless of `lo0`. Require the modified manifest to be committed in a clean throwaway experiment repository, and assert that the reason identifies capture or interface failure. The stated Debian container also needs `git` for `git_state()` and must have the experiment in a clean Git worktree; list those prerequisites. This makes the Linux test a falsification of the portability claim rather than a generic BLOCKED result.
4. **AC5 leaves a malformed-bundle path unspecified.** It checks a modified file but not a missing or malformed `verdict.json`, even though the summary promises one row per bundle and `verify-bundle` rejects it. Define whether such a row has null verdict/reason, an error field, or is omitted; require unverified data to be visibly untrusted in text and JSON. Also identify bundle discovery depth so “every bundle under a directory” is testable.
5. **AC6 does not test the stated clean-build rule.** The UDP build copies sources, and the TLS example has no build step, so both can pass while stale intermediate objects remain an issue for compiled experiments. The UDP example ignores `bin/` in Git, but the test helpers' `shutil.copytree()` still copies that leftover output; checking that only tracked files are copied addresses that real fixture failure. Keep the clean-build statement explicitly as author guidance, without treating AC6 as evidence that compiled experiments rebuild intermediate objects.

The required negative cases for unknown OS and tampered bundles are present. The missing negatives above matter because BLOCKED or FAIL alone can be produced for the wrong reason. Resolve the contradictions before freezing the acceptance criteria.
