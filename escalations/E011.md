## Design Deviation
```
Reported by: architect (Claude Opus 5.5, family anthropic), 2026-11-02, while preparing M08.

Every milestone (M01-M07, and the M08 being drafted) delivers changes to orchestrator.py,
but builders can never write it:
  - orchestrator.py:114 PROTECTED_PATTERNS = [orchestrator.py, orch, scripts/**, DESIGN.md,
    BASELINE.md, AGENTS.md, workflow.yaml, .git/**], checked first in _matches_ownership_rules
    (orchestrator.py:1301), before any workflow.yaml rule;
  - workflow.yaml ownership.builder: deny orchestrator.py, deny orch, deny scripts/** (commit 230be32).
So every builder dispatch for these milestones is rejected for ownership violations.

DESIGN.md 24.2 gives the builder "source tree", which does not exclude the orchestrator. The
protection (added by the F01/F02 audit fixes) guards a real invariant: a builder must not change
the code that judges it. But it is drawn at the wrong boundary. What must be protected is the
*governing* orchestrator (the copy on main that runs gates and verdicts), not the *subject* copy
in a build worktree.
```

## Resolution (architect PROPOSAL; human decides, G3, because DESIGN.md and workflow.yaml are implicated)
**Classification:** ARCHITECTURE
**Outcome:** REWORK
**Guidance:**
1. DESIGN.md 24.3 gains a "Governing and subject orchestrator" paragraph. Gates, verdicts, run-tests,
   ownership checks and state transitions are always executed by main's ./orch. A builder may change
   orchestrator.py and orch in its own worktree, like any other source file. That copy governs nothing
   until it has been VERIFIED and integrated (24.14). Builder tests that exercise it run sandboxed in the worktree.
   Reviewer design-01 showed this is not yet true: cmd_dispatch copies every allowed builder file into the invoking
   workspace (orchestrator.py:1078-1085), and REPO_ROOT is the directory of the executing file (orchestrator.py:35,134).
   So E011 also requires (a) dispatch to copy back only the attempt record, never code, and (b) the protected `orch`
   wrapper to execute main's orchestrator.py, located via git, wherever it is invoked (review design-02: this keeps M01's
   approved "works from main or any attempt worktree" interface, rather than forbidding worktree invocation), and
   (c) the prompt renderer to substitute {orch} with the absolute path of main's `orch`, not "./orchestrator.py"
   (orchestrator.py:659, review design-03). The renderer also stops rewriting the AGENTS.md examples into argument
   forms the CLI does not accept (`run-tests <id> <n> acceptance`, `--mutant`; orchestrator.py:661-673).
2. PROTECTED_PATTERNS becomes: orch, DESIGN.md, BASELINE.md, AGENTS.md, workflow.yaml, scripts/**, .git/**,
   .worktrees/**, pytest.ini, conftest.py, pyproject.toml (only orchestrator.py is removed). workflow.yaml drops "deny: orchestrator.py" and "deny: orch".
   scripts/** stays protected, because scripts/verify_gate.sh is the mechanical gate.
3. Bootstrap: builders cannot yet write orchestrator.py, so the human acting as orchestrator (24.3) applies
   items 1 and 2, plus (a) and (b), as a single manual commit that cites approvals/G3-E011.md. Regression tests:
   - a builder diff touching orchestrator.py is accepted, while one touching workflow.yaml, scripts/verify_gate.sh,
     conftest.py or acceptance/** is still rejected;
   - after a builder dispatch that changes orchestrator.py, main's orchestrator.py is byte-identical, and only build.md
     was copied;
   - `./orch status` invoked from an attempt worktree whose orchestrator.py was changed reports main's state and runs main's
     code (checked with a marker the changed copy would print).
   - a rendered verifier prompt contains no "./orchestrator.py" and invokes main's absolute `orch`; every example
     command in it parses with main's CLI (`--help` dry parse).
   - ./orch verify rejects a verification.yaml citing a run log that does not exist under main's runs/ (so logs
     produced by an attempt's own copy cannot be cited).
4. 24.13 affected-milestone list (G3 approves this list together with the DESIGN.md change):
   - M01: spec and interface unchanged. Its approved interface already says ./orch "works from the main worktree or any
     attempt worktree (it locates the main repository via git)", and rule 2 implements exactly that. Its AC1 already requires
     rejecting builder diffs outside ownership. M01 stays BUILDING with criteria_version 4846a491a8c1.
   - M02 (dispatch; DRAFT): affected, because its "retain worktree / copy artifacts" behavior must follow rule 1.
     It is already DRAFT, so no transition is needed; the M02 spec is revised before its review.
   - M03-M08: not affected.
